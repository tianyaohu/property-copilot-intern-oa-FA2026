## Fixed

### 1. Phone map hid load errors, the result cap, and any retry

**Severity:** high.

**Symptom.** Below `sm` the list pane has Tailwind `hidden` while Map is
selected (the default). The error empty-state, the "zoom in to see all" hint,
and the listing count all lived in that pane. A failed viewport query left an
empty map and no control to try again. Panning was the only retry, and it is
not obvious when the map itself looks idle.

**Repro before.** Playwright, 390×844, route `GET /properties` to
`400 {"error":"Viewport too large; zoom in"}`. The message was in the DOM
inside `div.hidden.sm:block` with a 0×0 box. Visible text was the title,
filters, map attribution, and Map/List — not the error.
`tests/browse-status.dom.test.tsx` failed with
`expected <div class="… hidden sm:block"> to be null`, and "Try again" was
not in the accessibility tree.

**Fix.** The status block renders outside the list pane (`order-first`, and
from `lg` in the list column so the map keeps the first grid row). "Try again"
bumps a reload key on the existing debounced fetch.

**Evidence after.** `tests/browse-status.dom.test.tsx` — 3 passed
(`renders a viewport error outside the pane…`, `retries a failed load without
requiring a pan`, `keeps the result-cap hint outside the pane…`).
Playwright: error box 324×20 at y=300, `hidden: false`, `inViewport: true`,
Try again visible. Truncation hint height 19 at y=263, not `display: none`.

### 2. Map/List bar covered the bottom of the phone map

**Severity:** medium.

**Symptom.** The map frame was `h-[70vh]`, which starts below the title and
filters. On a phone that runs the canvas under the fixed Map/List bar, so
attribution and the southern markers are not clickable. OpenStreetMap
attribution was partly covered.

**Repro before.** Playwright 390×844 after listings loaded: map bottom minus
bar top = **+66.8px** overlap. Screenshot showed the bar on top of the
attribution.

**Fix.** `components/map/mapFrame.ts` (`h-[calc(100dvh-28.5rem)]`, overridden
at `sm` and `lg`) is shared by the loading shell and the live map. 28.5rem
clears the header, title, filters, the bar, and the taller error block.

**Evidence after.** `tests/mapFrame.dom.test.tsx` —
`sizes the phone map to the visual viewport instead of a fixed 70vh` passed.
Playwright overlap (negative means a gap above the bar):

| Viewport | Before | After |
| --- | --- | --- |
| 390×844, listings loaded | +66.8px | −100px |
| 390×667, listings loaded | (same class) | −100px |
| 390×844, error banner showing | bar over the map | −10px |

Desktop map position is unchanged (still starts at y=212, height 702). The
~114px of map below an 800px-tall viewport is pre-existing; see deferred.

### 3. Clear left a rejected price draft on screen

**Severity:** medium.

**Symptom.** `PriceFilter` keeps invalid text locally and does not commit it.
The menu's Clear button writes `minRent` / `maxRent` back as `undefined`.
When nothing had been applied, those values do not change, the sync effect
does not run, and the field keeps showing "nope" plus the error.

**Repro before.** `tests/filters.dom.test.tsx` >
`clears a rejected price draft that never became the applied filter` failed:
after Clear, the Maximum input was still `"nope"`.

**Fix.** Clear price and Clear all bump a remount key on both price inputs.

**Evidence after.** That test passed. In the browser (1280×800): fill Maximum
with `nope`, the finite-number alert is visible; Clear leaves the input `""`
and the alert count 0.

### 4. Turning a bedroom count off left exact-match on

**Severity:** medium.

**Symptom.** Clicking the selected bedroom count clears `bedrooms` but not
`bedroomsExact`. The chip falls back to "Beds & baths" (exact-only is not an
active category) while the checkbox stays checked. The next count is an exact
match without the user asking again.

**Repro before.** `tests/filters.dom.test.tsx` >
`drops exact-match when the bedroom selection is toggled off` failed:
`expect(exact).not.toBeChecked()` received a checked box.

**Fix.** Toggling the selected count off clears `bedrooms` and `bedroomsExact`
together. Switching from one count to another still keeps exact-match.

**Evidence after.** That test passed (`rooms-filter` text is `{}`). In the
browser: select 2, check Use exact match, click 2 again; the checkbox is
unchecked.

### 5. A NaN latitude counted as inside the viewport

**Severity:** low.

**Symptom.** `isInBoundingBox` used relational comparisons. `NaN < min` and
`NaN > max` are both false, so a non-finite latitude passed whenever the
longitude was inside the box, including an antimeridian crossing. `refineToBox`
would have kept that point.

**Repro before.** `tests/geo.test.ts` >
`isInBoundingBox rejects a non-finite coordinate` failed:
`isInBoundingBox(NaN, -123.12, VANCOUVER_BOX)` was `true`.

**Fix.** Return false unless both coordinates are finite. Seed data is finite;
this stops a bad item from matching every viewport that contains its longitude.

**Evidence after.** That test passed.
`DYNAMODB_ENDPOINT=http://localhost:8000 npx vitest run tests/properties.integration.test.ts`
— 9 passed (the refine path still returns the downtown pair and excludes Kits).

### 6. `/favicon.ico` 404 on every page

**Severity:** low.

**Symptom.** Chrome requested `/favicon.ico` and logged
`Failed to load resource: the server responded with a status of 404`.
`curl -sI http://localhost:3000/favicon.ico` was `404` before the fix. No other
console error on a successful browse.

**Fix.** `app/favicon.ico` is a 32×32 PNG. Next serves it as
`Content-Type: image/x-icon`.

**Evidence after.** `curl -sI http://localhost:3000/favicon.ico` is `200` with
`Content-Length: 115`. A later browse run's console errors were only the
deliberate 400 from the viewport-too-large repro.
